# Milestone 2 — Integrated Core System

Target workflow: **Customer → Restaurant → Menu → Cart → Checkout → Order**
Suggested tag: `m2-integrated-system`

## 1. How M2 is organized (read this first)

The `m2-contracts` PR set up every shared file once, so feature work only touches files you own:

| Shared file (frozen — change only with a small PR the whole team agrees on) | What it fixes in place |
|---|---|
| `app/schemas/user_schema.py`, `cart_schema.py`, `order_schema.py` | Request/response shapes = the API contract |
| `app/core/exceptions.py` | Every domain error + its HTTP status |
| `app/schemas/error_schema.py` | Error body `{"error", "detail"}` + `error_responses()` for OpenAPI |
| `app/api/deps.py` | Dependency wiring, `get_current_user`, `require_roles` |
| `app/main.py` | All routers registered; DomainError → JSON, NotImplementedError → 501 |
| `app/repositories/json_file_store.py` | Load / atomic save / stable `next_id` for JSON files |
| `tests/conftest.py` | Isolated fixtures for every layer + `login_as` |

Every repository and service method already exists with a docstring describing its contract
and raises `NotImplementedError` (the API answers **501** until it's implemented).
Your job is to replace those bodies in **your** files and add tests.

into your constructor). Never open another subsystem's JSON file or edit its files.

## 3. Who calls whom

```
CartService  ──► CustomerService.get_active_customer      (deactivated customer → 403)
             ──► RestaurantService.get_restaurant_details (exists / isOpen)
             ──► RestaurantService.get_menu_item          (exists, price, availability)

OrderService ──► CustomerService.get_active_customer
             ──► CartService.validate_for_checkout        (revalidate prices + availability)
             ──► OrderRepository.create                   (persist FIRST)
             ──► CartService.close_cart                   (only AFTER the order is saved)
```

## 4. Merge order

1. `m2-contracts` (this PR)
2. In parallel: A (customers + auth), B (cart), D (restaurant fixes needed by cart: availability, owner-only menu edits, consistent `/restaurants` paths)
3. C (checkout + orders) — can be written in parallel using `login_as` and stub data, merged after B
4. C's integration test: register → sign in → browse → add to cart → checkout → order

## 5. Day-to-day rules

- One issue → one branch → one small PR. Aim to merge within 2–3 days.
- `git fetch && git merge origin/main` into your branch daily and before opening a PR; run `pytest`.
- Don't rename/move files or reformat whole files in a feature PR.
- Shared docs (`README.md`, `PROVENANCE.md`, this file): append to your own section only.
- Don't commit data files changed by running the app; only commit deliberate seed data.
- The PR author resolves conflicts, reruns tests, and re-requests review. Nobody approves their own PR.

## 6. Testing without waiting on auth

```python
def test_add_item(client, login_as):
    login_as("u01")   # pretend customer u01 is signed in
    response = client.post("/cart/items", json={"restaurant_id": "r01", "menu_item_id": "m01", "quantity": 2})
    assert response.status_code == 201
```

`login_as` overrides `get_current_user`. Tests of sign-in itself must call `/auth/login` instead.

## 7. API contract

| Method | Path | Role | Success | Errors |
|---|---|---|---|---|
| POST | `/auth/register` | public | 201 `CustomerResponse` | 409, 422 |
| POST | `/auth/login` | public | 200 `TokenResponse` | 401, 403, 422 |
| GET | `/customers/me` | customer | 200 `CustomerResponse` | 401, 403 |
| PATCH | `/customers/me` | customer | 200 `CustomerResponse` | 401, 403, 409, 422 |
| PUT | `/customers/me/address` | customer | 200 `CustomerResponse` | 401, 403, 422 |
| POST | `/customers/me/deactivate` | customer | 200 `CustomerResponse` | 401, 403 |
| GET | `/cart` | customer | 200 `CartResponse` | 401, 403 |
| DELETE | `/cart` | customer | 200 `CartResponse` | 401, 403 |
| POST | `/cart/items` | customer | 201 `CartResponse` | 401, 403, 404, 409, 422 |
| PATCH | `/cart/items/{menu_item_id}` | customer | 200 `CartResponse` | 401, 403, 404, 422 |
| DELETE | `/cart/items/{menu_item_id}` | customer | 200 `CartResponse` | 401, 403, 404 |
| POST | `/orders/checkout` | customer | 201 `OrderResponse` | 401, 403, 404, 409 |
| GET | `/orders` | customer | 200 `list[OrderResponse]` | 401, 403 |
| GET | `/orders/{order_id}` | any signed-in | 200 `OrderResponse` | 401, 404 |

Full schemas and examples: run the app and open `/docs`.
